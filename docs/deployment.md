# Deployment

The application runs on **AWS-App** as a Docker container behind the shared
nginx edge, and reads its data from the PostgreSQL instance on **AWS-Data**.

    https://ralsnahashho.dyndns.org:1000/awsmepplt

## Shape of it

| Piece | Where |
| --- | --- |
| Container `mepplms` | AWS-App, network `aws-app_aws-app`, port 3000, not published |
| Compose project `aws-mepplms` | `/opt/aws/mepplms/docker-compose.yml` |
| Runtime secrets | `/opt/aws/mepplms/.env` (mode 600, written by the deploy script) |
| Source for the image build | `/opt/aws/mepplms/src` |
| Edge routing | `/opt/aws/edge/apps/awsmepplt.conf`, included by the existing server block |
| Database | `pipeline_mep` on the AWS-Data cluster, role `pipeline_app` (address in `.deploy.env`) |

It is a compose project of its own rather than a service inside
`/opt/aws/docker-compose.app.yml`, because that file is regenerated by the
infrastructure sync and a hand-added service there would not survive the next
run. Joining the same network from outside reaches the same place.

## Releasing

    npm run release

Pushes the current branch to GitHub **and then** updates the portal, so the
repository and the running system never disagree. It refuses to run with a
dirty working tree, because the image is built from the working tree and
deploying dirty would put code on the server that exists in no commit. It
finishes by driving the deployed site in a browser; `-- --no-verify` skips
that.

To deploy without pushing:

    npm run deploy

That packs the working tree, uploads it, writes the compose file and the
runtime environment, builds the image on the server, restarts the container,
installs the nginx location and reloads the edge — then waits for the login
page to answer 200. It is safe to run repeatedly, and it touches nothing
outside `/opt/aws/mepplms` and that one edge config file.

`--no-build` skips the image build, for when only the compose file or the
nginx config changed.

SSH credentials come from `.deploy.env`; the database password and the other
runtime values come from `.env`. Both are git-ignored and neither is ever
printed or committed.

## The base path is compiled in

Next writes the prefix into every asset URL, every Server Action endpoint and
every `<Link>` **at build time**. So `/awsmepplt` appears in three places
that must agree:

1. `APP_BASE_PATH` — the build argument in `deploy/docker-compose.yml`.
2. The `location` blocks in `deploy/awsmepplt.conf`. The prefix is passed
   through to the container untouched, never stripped.
3. Nothing at runtime. An image built for one prefix cannot be served at
   another.

Change one alone and the HTML arrives while every script behind it 404s,
which renders as an unstyled page that half works.

Three things Next does *not* prefix for you, and which the code therefore
prefixes by hand through `withBasePath()` in `src/lib/base-path.ts`:

- hand-written `fetch()` and `EventSource` URLs,
- `metadata.icons` in `src/app/layout.tsx`,
- the `signOut({ callbackUrl })` target, because the browser navigates there
  itself.

The opposite mistake is just as easy: anything handed to the **Next router**
or to `<Link>` must *not* be prefixed, because they apply the base path
themselves. That is why `middleware.ts` stores an unprefixed `callbackUrl`
while prefixing the redirect target it sits in.

## Auth.js and the prefix

`authConfig.basePath` stays at its default `/api/auth`. Next strips the
deployment prefix before the request reaches the route handler, so the server
really does see `/api/auth/...`; telling Auth.js otherwise makes it fail to
parse the action and answer `400 Bad request`. Only the browser needs the
prefix, and it gets it from `<SessionProvider basePath>`.

`AUTH_URL` is set to `https://ralsnahashho.dyndns.org:1000/api/auth` — the
public **origin**, with the path left at `/api/auth`. Both halves matter and
for opposite reasons:

- The path is where Auth.js takes its base path from, so a prefixed value
  there brings back the same 400.
- The origin is needed because Next's standalone server builds `request.url`
  from the address it binds to, which is `0.0.0.0`. Without it, Auth.js
  resolves the sign-out callback against `http://0.0.0.0:3000` and sends the
  browser to a host that does not exist.

## The address bar must keep the prefix

The pipeline mirrors its filters into the URL with `history.replaceState`
rather than the router, to avoid re-running the server component on every
keystroke. `usePathname()` reports the path *without* the prefix, so it has to
be put back before writing — otherwise the address bar quietly loses it, and
since a Server Action posts to whatever the current URL is, the next save goes
to a path nginx does not route. It presents as "an unexpected response was
received from the server" on a screen that worked a moment earlier, which
reads like a save bug rather than a routing one.

## Database migrations

The image does not carry the Prisma CLI, so migrations are applied from a
workstation that can reach the database:

    npm run db:deploy

Do this **before** deploying an image that expects the new schema.

## Serving

`next start` refuses to serve a `standalone` build — the container runs
`node server.js` from Next's traced output. Locally, the same thing:

    npm run build && node .next/standalone/server.js

after copying `.next/static` and `public` beside it.

## Verifying

    BASE_URL=https://ralsnahashho.dyndns.org:1000/awsmepplt node scripts/ui-check.mjs

Drives a real browser through every screen and fails on any console error,
page error or failed request. `UI_USER` and `UI_PASS` (or
`SEED_ADMIN_PASSWORD` in `.env`) supply the credentials.

**It is read-only unless told otherwise.** Two steps write - creating a user
and saving an inline edit - and they are skipped unless `UI_ALLOW_WRITES=1`.
`npm run release` never sets it, because this runs against the live system and
anything it creates stays there. Run the full set against a local server:

    UI_ALLOW_WRITES=1 BASE_URL=http://localhost:3100/awsmepplt node scripts/ui-check.mjs

A system with no company yet is treated as a legitimate state: the pipeline
checks are skipped rather than failed, unless the empty state itself is
wrong.
